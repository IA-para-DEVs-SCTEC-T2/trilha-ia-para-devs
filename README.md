# Trilha IA para Devs

Material de apoio para a disciplina de Inteligência Artificial aplicada ao desenvolvimento de software.

## Descrição

Este repositório reúne slides, exemplos práticos, atividades, materiais instrucionais, templates e orientações para o mini-projeto avaliativo. O conteúdo acompanha as semanas do módulo e serve como referência durante e após as aulas.

## Objetivo

Apoiar o desenvolvimento de habilidades práticas de engenharia de software assistida por IA, cobrindo desde engenharia de contexto e prompts até testes automatizados, documentação técnica e automação de fluxos com GitHub.

## Público-alvo

Estudantes de desenvolvimento de software com conhecimento básico de programação, Git e GitHub.

---

## Organização das pastas

```
trilha-ia-para-devs/
├── aulas/          # Conteúdos organizados por semana (slides, hands-on, desafios, materiais)
├── atividades/     # Desafios e exercícios para resolução e entrega via Pull Request
├── exemplos/       # Referências práticas reutilizáveis (prompts, GitHub, Postman, testes)
├── materiais/      # Guias, templates, referências bibliográficas e sugestões de leitura
└── mini-projeto/   # Requisitos, critérios, orientações e entregas do projeto avaliativo
```

### aulas/

Concentra os conteúdos organizados por semana, incluindo slides em PDF, materiais de apoio, práticas guiadas (hands-on), desafios e exemplos utilizados durante as aulas. Cada semana possui sua própria pasta com a estrutura adequada ao tema.

Subpastas recorrentes dentro de cada semana:

- **`hands-on/`** — Práticas guiadas, códigos-base, exercícios de implementação e exemplos para reprodução durante ou após a aula.
- **`desafios/`** — Atividades práticas propostas para consolidar o conteúdo da semana, geralmente com enunciado, contexto, critérios e orientações de entrega.
- **`materiais/`** — Materiais instrucionais em PDF, guias complementares e referências de apoio específicas da semana.

### atividades/

Contém os enunciados e espaços para entrega das atividades semanais. Cada aluno deve criar sua própria branch, resolver a atividade e abrir um Pull Request.

### exemplos/

Contém arquivos de referência prática sobre automações, GitHub, Postman, prompts e testes. Não são entregas dos alunos — são modelos para consulta e reutilização.

### materiais/

Reúne guias de referência, templates reutilizáveis, referências bibliográficas e sugestões de leitura. Útil para consulta durante as atividades e o mini-projeto. Inclui subpastas:

- `guias/` — Guias práticos sobre Git, testes, Postman, Markdown, documentação e uso de IA.
- `templates/` — Modelos de PRD, user stories, issues, pull requests, casos de teste e relatórios.
- `referencias/` — Links e referências externas organizadas por tema.
- `ebooks/` — Sugestões de leitura complementar.

### mini-projeto/

Concentra todas as informações do projeto avaliativo: requisitos, critérios de avaliação, user stories, diagramas, orientações de entrega e checklist. Consulte [`mini-projeto/README.md`](mini-projeto/README.md) para detalhes.

## Fluxo recomendado para os alunos

1. **Revise os slides da semana** em `aulas/semana-XX/` antes ou após a aula.
2. **Abra os materiais instrucionais em PDF** na subpasta `materiais/` da semana correspondente.
3. **Execute os hands-on** em `aulas/semana-XX/hands-on/` para praticar o conteúdo.
4. **Resolva os desafios** em `aulas/semana-XX/desafios/` para consolidar o aprendizado.
5. **Consulte templates e exemplos** em `materiais/templates/` e `exemplos/` para referência.
6. **Aplique os aprendizados no mini-projeto** em `mini-projeto/`.

## Uso de IA no desenvolvimento

- Use IA como ferramenta de apoio, não como substituto do raciocínio.
- Sempre revise o que a IA gera antes de usar.
- Registre os prompts utilizados em cada atividade.
- Documente as decisões tomadas com base nas sugestões da IA.
- Consulte [`exemplos/prompts/`](exemplos/prompts/) para modelos de prompts reutilizáveis.
- Consulte [`materiais/guias/guia-uso-de-ia-no-desenvolvimento.md`](materiais/guias/guia-uso-de-ia-no-desenvolvimento.md) para boas práticas.

## Git e GitHub

- Nunca trabalhe diretamente na branch `main`.
- Crie uma branch para cada atividade ou funcionalidade.
- Faça commits pequenos e com mensagens descritivas.
- Abra Pull Requests para revisão antes de fazer merge.
- Consulte [`exemplos/github/`](exemplos/github/) para modelos de Issues, PRs e commits.

### Convenções de branch

| Prefixo | Uso |
|---------|-----|
| `feat/` | Nova funcionalidade |
| `fix/` | Correção de bug |
| `docs/` | Documentação |
| `test/` | Testes |
| `chore/` | Tarefas de manutenção |

Exemplo: `feat/tela-login`, `docs/readme-semana-05`

### Convenções de commit

```
feat: adiciona tela de login
fix: corrige validação de senha vazia
docs: atualiza README com instruções de entrega
test: adiciona testes unitários para cálculo de frete
```

## Atividades e desafios

- Leia o enunciado completo antes de começar.
- Registre os prompts usados em um arquivo `prompts-usados.md` dentro da sua entrega.
- Inclua evidências de execução (prints, logs ou saídas de terminal).
- Siga os critérios de qualidade descritos em cada atividade.

O mini-projeto é o trabalho avaliativo do módulo. Consulte [`mini-projeto/README.md`](mini-projeto/README.md) para entender o que deve ser entregue, como organizar o repositório e como usar GitHub Issues, branches e Pull Requests no desenvolvimento.

## Critérios gerais de qualidade

- Código funcional e testado.
- Documentação clara e objetiva.
- Commits com mensagens descritivas.
- Uso consciente e registrado de IA.
- Evidências de execução incluídas nas entregas.
- Estrutura de repositório organizada.
