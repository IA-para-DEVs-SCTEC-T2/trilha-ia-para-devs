Você é um especialista em Python, LangGraph e didática de ensino.

Implemente uma solução completa e autocontida para o desafio “Agente seguro e governado”.

A solução deve criar, do zero, um agente de atendimento de loja online usando LangGraph. Não reaproveite funções, variáveis, classes ou graphs criados anteriormente no notebook.

Objetivo:
Criar um agente que receba uma solicitação do usuário, interprete a intenção, avalie segurança, classifique risco, aplique política de autorização, solicite aprovação humana quando necessário, execute ou bloqueie tools e gere uma resposta final rastreável.

Requisitos:
- Use Python e LangGraph.
- Não use LLM.
- Não use Gradio.
- Não use banco de dados.
- Não use APIs externas.
- Use nomes de variáveis em português.
- Use pprint para exibir os resultados.
- Organize o código em blocos curtos e fáceis de explicar.

Regras de negócio:

1. A role do usuário sempre vem de CLIENTES[cliente_id].
   Nunca aceite role informada na mensagem do usuário.

2. Interpretação da intenção:
   - Se a mensagem tiver “status” ou “consultar” → consultar_pedido.
   - Se tiver “cancel” → cancelar_pedido.
   - Se tiver “reembolso” ou “reembolsar” → reembolsar_pedido.
   - Se tiver “endereço” ou “endereco” → atualizar_endereco.
   - Se tiver “apague”, “delete”, “exclua” ou “remova cadastro” → apagar_cadastro.
   - Caso contrário → desconhecida.
   - Extraia pedido_id com regex.
   - Extraia novo_endereco quando a mensagem tiver “para ...”.

3. Segurança:
   Detecte prompt injection se a mensagem tiver termos como:
   - ignore instruções
   - ignore todas as instruções
   - delete
   - token
   - senha
   - segredo
   - credencial
   - bypass

   Se detectar prompt injection:
   - injection_detectada = True
   - risco = critico
   - decisao = bloquear
   - nenhuma tool pode ser executada.

4. Classificação de risco:
   - consultar_pedido → baixo
   - atualizar_endereco → medio
   - cancelar_pedido → alto
   - reembolsar_pedido → alto
   - apagar_cadastro → critico
   - desconhecida → medio
   - prompt injection → critico

5. Política de autorização:
   - consultar_pedido: permitido para qualquer role.
   - atualizar_endereco: permitido apenas para atendente ou gerente.
   - cancelar_pedido: permitido apenas para gerente e exige aprovação humana.
   - reembolsar_pedido: permitido apenas para gerente e exige aprovação humana.
   - apagar_cadastro: sempre bloqueado.
   - prompt injection: sempre bloqueado.
   - intent desconhecida: não executa tool; responde pedindo mais informações.

6. Execução de tools:
   - A tool só pode ser executada depois da política.
   - Ação sensível só executa se aprovacao_humana is True.
   - Se aprovacao_humana is None em ação sensível, o agente deve solicitar aprovação.
   - Se aprovacao_humana is False em ação sensível, o agente deve bloquear.
   - Ações bloqueadas nunca executam tool.

Roteamento:
- decisao == "bloquear" → bloquear
- decisao == "permitir" → executar_tool
- decisao == "pedir_aprovacao" e aprovacao_humana is True → executar_tool
- decisao == "pedir_aprovacao" e aprovacao_humana is None → solicitar_aprovacao
- decisao == "pedir_aprovacao" e aprovacao_humana is False → bloquear
